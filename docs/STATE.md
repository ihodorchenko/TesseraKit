## Принятые решения

Правило из образца pchelovod: «подтверждено» — ответ пользователя; «предложено» — решение агента,
которое пользователь видел, но явно не подтверждал: на нём можно строить план, но не необратимые
шаги.

| | Решение | Почему | Статус |
|---|---|---|---|
| D1 | План и риски фиксируются файлами `PLAN.md` и `RISK.md` в `docs/`; статусы задач — эмодзи ✅ / 🔶 / ⬜ | отслеживаемость «что осталось»; формат по образцу pchelovod | **подтверждено 29.10.2026** |
| D2 | Эпики выполняются **строго последовательно** (E0 → E1 → E2 → E3 → E4 → E5); параллелизм — внутри эпика саб-агентами с непересекающимися write-скоупами | проще апрув-гейты и история git; порядок диктуют зависимости от Core | **подтверждено 29.10.2026**; для E9–E10 уточнено D19 |
| D3 | CI (GitHub Actions) в v1 не добавляем; перед каждым коммитом — локальные `swift build` + `swift test` | решение пользователя | **подтверждено 29.10.2026** |
| D4 | Коммит — только после апрува пользователя; эпик закрывается PR из `task/*` в `dev`; в `main` — отдельным PR по готовности | правило `AGENTS.md` | **подтверждено (AGENTS.md)** |
| D5 | Example-приложение (хост для ручной проверки) в MVP не входит — «Вне плана» в `PLAN.md` | для SPM-пакета не обязательно | **заменено D16 (29.10.2026)** |
| D6 | Перед каждой задачей агент описывает, что будет сделано, и приступает только после апрува пользователя; к следующей задаче переходит только по явной команде пользователя | правило процесса, зафиксировано в `AGENTS.md` | **подтверждено 29.10.2026** |
| D7 | Исполнение задач — саб-агентами (модель Flash, режим рассуждений High); Lead только контролирует выполнение и сообщает пользователю финальный результат | требование пользователя, зафиксировано в `AGENTS.md` | **подтверждено 29.10.2026** |
| D9 | Пакет — только iOS (iOS 15+); Mac — только в совместимости (Mac Catalyst, `.macCatalyst(.v15)` в `platforms`); локальная проверка компиляции на Mac-хосте — через macabi-трипл | требование пользователя («оставляем только iOS, Mac — только в совместимости») | **подтверждено 29.10.2026** |
| D10 | Гейт тестов: `swift test` на macOS-хосте невозможен для UIKit-кода — тесты гоняются через `xcodebuild test -scheme TesseraKit-Package -destination 'platform=iOS Simulator,name=iPhone 17'` (в среде DSH — с полным доступом к файловой системе) | выяснено при гейте E1 (dlopen macabi-бандлов отклоняется, «incompatible platform») | предложено 29.10.2026 |
| D11 | Сообщения коммитов и pull request'ов (заголовки и описания) — на английском; язык документации (`AGENTS.md`, `docs/`) остаётся русским | требование пользователя | **подтверждено 29.10.2026** |
| D12 | E4: рабочий стол — **ярлыки и папки**; ярлык = просто действие: модель `id`, `title`, `icon`, `action: () -> Void`, `badge` (красная точка/счётчик внимания); поля `type` нет | уточнение пользователя к MVP E4 | **подтверждено 29.10.2026** |
| D13 | Обе боковые страницы пейджера **опциональны**: левая (хук) и правая (список) показываются, только если хост их задал; пейджер — от 1 до 3 страниц | уточнение пользователя | **подтверждено 29.10.2026** |
| D14 | Папки: создание папки, добавление ярлыка в папку и перемещение между папками — только через **функцию одобрения** хоста (дефолт — разрешено) | уточнение пользователя | **подтверждено 29.10.2026** |
| D15 | Live-плитки **закладываются в E4** (флипы, стахгер, паузы, Reduce Motion — по §4 STARTSCREEN-IOS-DESIGN); размеры ярлыков — **4 вида** (1×1, 2×2, 4×2, 4×4) | уточнение пользователя | **подтверждено 29.10.2026** |
| D16 | Example-хост `Example/TesseraKitExample/TesseraKitExample.xcodeproj` добавляется для ручной проверки компонентов (bundle id `by.TesseraKit.example`); `.xcodeproj` коммитится — исключение в `AGENTS.md` | требование пользователя («нужно как-то посмотреть руками») | **подтверждено 29.10.2026** |
| D17 | Папки рабочего стола: нативное WP-поведение (реализовано в E7: панель раскрывается ПОД плиткой папки, плитка остаётся, рост высоты 0→панель, каскад иконок без перераскладки, перехват folderTapHandler; на плитке папки при раскрытии скрывается превью 2×2; в панели — плитки small как на столе с подложкой/бэйджами); уточнение W2 (E10.1): панель встаёт под „полосой папки“ — строки папки плюс пересекающие их плитки | требование пользователя (поведение как в Windows Phone) | **подтверждено 29.10.2026** |

| D19 | Эпики исправлений E9 и E10 выполняются не последовательно, а общими волнами по слоям и файлам: W1 Core → (W2 модель плиток → W3 сетка → W4 drag) параллельно с треками T1 экран рабочего стола, T2 live-плитки и список, T3 Pivot, T4 Panorama → W5 финал (покрытие, документы, локализация).
