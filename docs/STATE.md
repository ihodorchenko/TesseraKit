## Чего нет

- **Эпики E0–E12 закрыты**, релиз v0.3.0 выпущен; E11/E12 в `dev` ещё не выпущены в `main`. Открыты E14–E16 (см. [`PLAN.md`](PLAN.md)); E13 закрыт.
- **E12.8 — остаточные проверки (🔶)**: подсветка слияния и haptic в процессе удержания (в кадре не снята; haptic в симуляторе не наблюдается), поворот посреди живого drag и после drop, VoiceOver, RTL и Dynamic Type на вкладке «Старт» Example (VoiceOver-действия папок E11.5 и Dynamic Type плиток E12.6 покрыты тестами, но не прогонялись вживую на полном StartScreen). Нужен выделенный симулятор/устройство (R24).
- **Живые плитки в edit-режиме продолжают флипаться** — решено оставить как есть (D37, закрывает Q7); дизайн-док этого не оговаривал (наблюдение E12.8).
- **Папка меняет размер, как в W10M**: «папку можно менять в размере» — уже так (пользователь, E12.2); при создании всегда `.medium`, сохранённый размер при загрузке не нормализуется (п. 41).
- **Контракт хоста: `canonicalizeVisibleOrder(columns:)` после `setCatalog`/`load`** — координатор канонизирует порядок только на входе в edit и старте drag (E12.10); вопрос Q8 (канонизация в самом `TileStore.load`) снимается эпиком E14 (D30): с явными координатами порядок чтения не является моделью (R22).
- **Строго компактная упаковка**: настоящих пустот на сетке пока нет, плитка не закрепляется в дыре; решение принято — вариант Б (D30), работа в эпике E14 (R23).
- **Известные ограничения** (не блокируют релиз):
  - transient-предупреждения `[CollectionView] Received layout attributes with an invalid index path`
    в windowed-тестах — рассинхрон кастомной раскладки на границе кадра при count-changing
    `performBatchUpdates`, детерминированно не воспроизводится;
  - канонизация порядка `TileStore` включается только при известном числе колонок (`columns` —
    opt-in; без него видимый порядок может расходиться с экранным);
  - контракт `startDrag`: к моменту захвата снимок сетки обязан совпадать с моделью, иначе drag
    не начинается (в DEBUG — assertion); хосту нужно применять снимки store;
  - арбитраж/регистрация в тестах Panorama — проверен контракт (`TesseraGestureArbiter`/
    `axisDecision`, публичный `registerVerticalOwner`, живой child `UIScrollView`, блокировка и
    восстановление), а приватная точка `.began` контроллера без шва в `Sources` не исполняется;
  - `Bundle.module` у `TesseraStartScreen`: пакет обязан шипить ресурсный бандл
    `TesseraKit_TesseraStartScreen.bundle`; если потребитель скопировал модуль без ресурсов,
    обращение к строкам падает с `fatalError` (требование к интеграторам);
  - static-scan в `LocalizationTests` проверяет отсутствие кириллических UI-литералов только при
    доступном дереве исходников: в бинарной/CI-сборке тест уходит в `XCTSkip`, а при доступности
    сканирует только верхний уровень каталога `Sources/TesseraStartScreen`;
  - внутренние a11y-строки и строки экрана папки хостом не переопределяются — для нового языка
    нужны таблицы en/ru и правила плюрализации (или `.stringsdict`).
- **CI** — по решению D3 не добавляем: перед коммитом локальные `swift build` + `xcodebuild test`.
- **Вне плана** (см. [`PLAN.md`](PLAN.md)): публикация пакета в индексах SPM / документации на
  веб-площадке и фичи v2 (edge-swipe плагин, `TesseraPerformanceKit`, повторяющаяся лента Pivot,
  фото-слайдшоу в плитках и прочее «отрезанное в v1»).

## Принятые решения

Правило из образца pchelovod: «подтверждено» — ответ пользователя; «предложено» — решение агента,
которое пользователь видел, но явно не подтверждал: на нём можно строить план, но не необратимые
шаги.
