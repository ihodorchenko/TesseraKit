## Чего нет

- **Эпики E0–E14 закрыты** (E14 — после E14.9), релиз v0.3.0 выпущен; E11–E14 в `dev` ещё не выпущены в `main`. Открыты E15–E16 (см. [`PLAN.md`](PLAN.md)).
- **E14 — остаточные ручные проверки** (не делались, нужен симулятор/устройство, R24–R27): миграция реального `tiles.json` v1, haptic и подсветка слияния, VoiceOver (порядок по ячейкам, фокус после unpin/resize/drop/распада папки, прокрученная сетка, unpin в панели), поворот и RTL, Dynamic Type, drag из панели папки, артефакты анимации превью после сортировки порядка сетки (E14.7), анимация замены папки ярлыком и закрытия панели при распаде (E14.8). Сценарии — «Ручная проверка E14» в [`PLAN.md`](PLAN.md).
- **E12.8 — остаточные проверки (🔶)**: подсветка слияния и haptic в процессе удержания (в кадре не снята; haptic в симуляторе не наблюдается), поворот посреди живого drag и после drop, VoiceOver, RTL и Dynamic Type на вкладке «Старт» Example (VoiceOver-действия папок E11.5 и Dynamic Type плиток E12.6 покрыты тестами, но не прогонялись вживую на полном StartScreen). Нужен выделенный симулятор/устройство (R24).
- **Живые плитки в edit-режиме продолжают флипаться** — решено оставить как есть (D37, закрывает Q7); дизайн-док этого не оговаривал (наблюдение E12.8).
- **Папка меняет размер, как в W10M**: «папку можно менять в размере» — уже так (пользователь, E12.2); при создании всегда `.medium`, сохранённый размер при загрузке не нормализуется (п. 41).
- **Канонизации порядка больше нет** (E14.5, E14.6; вопрос Q8 снят, R22 закрыт): модель хранит координаты, порядок чтения — производное; `canonicalizeVisibleOrder` и опциональный `columns` для неё удалены. Контракт хоста: строить снимок `TileStore.snapshot(columns:)` (с таблицей ячеек) и применять снимки store; `startDrag` по-прежнему требует, чтобы сетка совпадала с моделью.
- **Папка не бывает из 0–1 ярлыков (D45, E14.8)**: в W10M §6.9 состояние «осталась одна плитка» не описано (по аналогии папка сохранялась с одной миниатюрой); решением пользователя 13.11.2026 такая папка распускается, последний ярлык встаёт на место папки со своим размером. Это осознанное отступление от эталона (W10M-CONFORMANCE, группа «Папки»). Невидимых (вне каталога) членов у папки после `setCatalog`/`load` не бывает: каталог авторитетен для её содержимого, поэтому правило считает только видимые ярлыки; папка из одного ярлыка, прочитанная до регистрации каталога, ждёт его и распускается на `setCatalog`. Не проверено на устройстве: VoiceOver-фокус после закрытия панели распавшейся папки и анимация замены папки ярлыком в кадре.
- **Настоящие пустоты на сетке есть** (D30, E14; R23 закрыт): `tiles.json` версии 2 хранит `row`/`column` и ширину холста, дыры остаются после открепления, слияния, drop'а и уменьшения плитки, пустая строка схлопывается только на drop (D31), коллизии выталкивают плитки вниз каскадом, drop выбирает клетку (внизу — цель «новая строка»), при другой ширине холста показывается проекция по порядку чтения без дыр (D32). Индексного API нет (D33). Упаковка по порядку (`pack`/`packCompact`) осталась только как откат раскладки, миграция v1 → v2, проекция D32 и раскладка первого запуска; подробности — STARTSCREEN-IOS-DESIGN, «Отступления реализации (E14)», п. 49–56.
  - Остаточные ограничения E14 (не блокируют релиз): на drop со схлопыванием строки хост получает два `onChange` (известное ограничение из PR #53, не менялось); невидимые (вне каталога) ярлыки хранят ячейку, но в раскладке не участвуют.
- **Известные ограничения** (не блокируют релиз):
  - transient-предупреждения `[CollectionView] Received layout attributes with an invalid index path`
    в windowed-тестах — рассинхрон кастомной раскладки на границе кадра при count-changing
    `performBatchUpdates`, детерминированно не воспроизводится;
  - контракт `startDrag`: к моменту захвата снимок сетки обязан совпадать с моделью, иначе drag
    не начинается (в DEBUG — assertion); хосту нужно применять снимки store;
  - арбитраж/регистрация в тестах Panorama — проверен контракт (`TesseraGestureArbiter`/
    `axisDecision`, публичный `registerVerticalOwner`, живой child `UIScrollView`, блокировка и
    восстановление), а приватная точка `.began` контроллера без шва в `Sources` не исполняется;
  - `Bundle.module` у `TesseraStartScreen`: пакет обязан шипить ресурсный бандл
    `TesseraKit_TesseraStartScreen.bundle`; если потребитель скопировал модуль без ресурсов,
    обращение к строкам падает с `fatalError` (требование к интеграторам);
  - static-scan в `LocalizationTests` проверяет отсутствие кириллических UI-литералов только при
    доступном дереве исходников: в бинарной/CI-сборке тест уходит в `XCTSkip`, а при доступности
    сканирует только верхний уровень каталога `Sources/TesseraStartScreen`;
  - внутренние a11y-строки и строки экрана папки хостом не переопределяются — для нового языка
    нужны таблицы en/ru и правила плюрализации (или `.stringsdict`).
- **CI** — по решению D3 не добавляем: перед коммитом локальные `swift build` + `xcodebuild test`.
- **Вне плана** (см. [`PLAN.md`](PLAN.md)): публикация пакета в индексах SPM / документации на
  веб-площадке и фичи v2 (edge-swipe плагин, `TesseraPerformanceKit`, повторяющаяся лента Pivot,
  фото-слайдшоу в плитках и прочее «отрезанное в v1»).

## Принятые решения

Правило из образца pchelovod: «подтверждено» — ответ пользователя; «предложено» — решение агента,
которое пользователь видел, но явно не подтверждал: на нём можно строить план, но не необратимые
шаги.
