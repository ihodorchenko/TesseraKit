# Риски

> Парный файл: [PLAN.md](PLAN.md). Источники — разделы «Риски» в `docs/` и организационные риски
> процесса (`AGENTS.md`). Оценки качественные, без эстимейтов; при срабатывании риска объём работ
> пересматривается в [PLAN.md](PLAN.md). Новые риски дописываются сюда же, при закрытии эпика —
> ревизия.

| | Риск | Влияние | Вероятность | Подробности |
|---|---|---|---|---|
| R1 | Переабстракция Core — раздувание до «фреймворка всего» | высокое | средняя | Правило трёх (CORE-IOS-DESIGN §6); на гейте E1 — ревизия каждой публичной сущности Core. |
| R2 | Утечка специфики в Core (термины плиток/лент/холстов) | среднее | средняя | В Core — только «страницы, прогресс, слои»; grep-проверка имён компонентов перед коммитом. |
| R3 | Хрупкость обновлений Core — изменение регрессирует три библиотеки | высокое | высокая | Контрактные тесты E1.7 до компонентов; политика deprecation; полный `swift test` перед каждым PR. |
| R4 | Конфликт жестов «вариант B» — пейджер × вертикальный скролл ребёнка, bounce на стыке | высокое | высокая | Арбитраж по доминирующей оси (E1.4) с тестами; ручная проверка с `UICollectionView` внутри секции. |
| R5 | «Уплывание» индикатора Pivot при разной ширине заголовков | среднее | высокая | Формула `lerp(center[i], center[i+1], frac(t))`, не `t × constWidth`; тесты на случайных наборах (E2.7). |
| R6 | Двойная анимация: анимированный `setContentOffset` + делегат скролла | среднее | средняя | Правило одного писателя `contentOffset`; защита обработчика тапа; тест синхронизации (E2.7). |
| R7 | `pagingEnabled` — чёрный ящик: нет контроля децелерации и «прыжков через страницы» | низкое | низкая | Приемлемо по PIVOT-IOS-DESIGN; при необходимости — кастомный снап E1.2, не патч поверх. |
| R8 | Drag-перестановка на переменной сетке — главный источник багов проекта | высокое | высокая | Собственный drag-координатор (не нативный interactive movement); тесты на случайных конфигурациях (E4.7) с самого начала. |
| R9 | Жестовый стек StartScreen: пейджер × сетка × список × системный edge-жест | высокое | высокая | Трёхсторонний арбитраж E1.4; политика «корневой экран без back-навигации»; в стеке — отключение/уступка `interactivePopGestureRecognizer`. |
| R10 | Джиттер флипов при скролле | среднее | средняя | Только трансформы, никакого layout; стахгер батчами; паузы вне экрана/в фоне; Reduce Motion → статичный фронт. |
| R11 | Культурный риск — чужеродные iOS паттерны (панорама, живой рабочий стол) | на позиционирование | высокая | Компоненты — опциональный стиль, не замена нативной навигации; README позиционирует так же. |
| R12 | Просадки SwiftUI-секций на iOS 15 — каждый `UIHostingController` со своим layout-циклом | среднее | средняя | Переиспользование хостингов (E1.5), запрет пересоздания при обновлении состояния; ленивая загрузка ±1 + prefetch. |
| R13 | Инертный свайп упирается в ленивую загрузку | среднее | средняя | Prefetch секций/страниц (аналог `UICollectionViewDataSourcePrefetching`); хук до снапа. |
| R14 | Случайное использование API новее iOS 15 (`@Observable`, `scrollTargetBehavior`, `@Entry`…) | среднее | средняя | Чек-лист в промпте каждого саб-агента; grep-аудит запрещённых символов на гейте эпика. |
| R15 | Конфликты параллельных саб-агентов — правки одних файлов, рассинхрон статусов | среднее | средняя | Непересекающиеся write-скоупы на подзадачу (таблицы в PLAN.md); лид ревьюит полный diff эпика. |
| R16 | Регрессия после мерджа в `dev` — фазы последовательны, но `dev` может уйти вперёд | среднее | низкая | Перед эпиком — свежий `git pull origin dev` и rebase ветки; `swift test` после rebase. |
| R17 | Расхождение кода и `docs/` — реализация отклоняется от проектных документов | среднее | средняя | Отклонение → обновление документа в той же ветке; проверка на гейте эпика. |
| R18 | Объём StartScreen недооценён — самый крупный эпик может расползтись | высокое | средняя | Жёсткие границы MVP по документу (отрезанное в v1 перечислено в PLAN.md); при переполнении — дробление E4 на две ветки. |
| R19 | План и риски устаревают | процессное | средняя | Обновление после каждой задачи (правило из PLAN.md); ревизия рисков при закрытии эпика. |
