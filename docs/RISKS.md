# Risk register

Qualitative register of technical and product risks. Impact and likelihood are rough (low, medium, high).
Closed risks stay in the table with the reason.

| Id | Risk | Impact | Likelihood | Mitigation / status |
|---|---|---|---|---|
| R1 | Over-abstraction: Core grows into a framework for everything. | High | Medium | Rule of three: a mechanism enters Core only if two components need it. Every public Core type is reviewed against it. Open. |
| R2 | Component-specific terms (tiles, strips, canvases) leak into Core. | Medium | Medium | Core speaks only of pages, progress and layers; names of components are grepped before changes. Open. |
| R3 | Core changes regress all three libraries. | High | High | Contract tests for progress, snapping and arbitration; a deprecation policy for the public surface; the full suite runs before every merge. Open. |
| R4 | Gesture conflict between the pager and a child's vertical scrolling, bounce at the seam. | High | High | Axis-dominance arbitration in `TesseraGestureArbiter`, covered by tests; manual check with a collection view inside a section. Open. |
| R5 | The Pivot indicator drifts when header widths differ. | Medium | High | Interpolate between measured centres (`lerp(center[i], center[i+1], frac(t))`), never `t * constantWidth`; tests on random header sets. Closed: covered by tests. |
| R6 | Double animation: an animated `setContentOffset` combined with scroll delegate callbacks. | Medium | Medium | Single writer of `contentOffset`; guarded tap handler; synchronisation tests. Closed. |
| R7 | `pagingEnabled` is a black box (no control over deceleration or skipped pages). | Low | Low | Accepted for Pivot; the custom snapping mode exists where control is needed. Closed. |
| R8 | Drag reordering on a variable grid is the main source of bugs. | High | High | Own drag coordinator instead of native interactive movement; randomized layout tests. The risk materialised (more than twenty drag and folder defects were found and fixed), so it stays high; see R20. Open. |
| R9 | Gesture stack of the start screen: pager, grid, list and the system edge gesture compete. | High | High | Three-way arbitration; the root screen has no back navigation; inside a navigation stack the left-edge policy yields to the system gesture. Open. |
| R10 | Jitter of tile flips while scrolling. | Medium | Medium | Transforms only, no layout; staggered batches; pauses off screen and in the background; Reduce Motion shows a static face. Closed. |
| R11 | Cultural risk: Windows-Phone-style patterns are foreign to iOS. | Positioning | High | Components are an opt-in style, not a replacement for native navigation, and the README says so. Open. |
| R12 | SwiftUI sections on iOS 15 are slow because each hosting controller has its own layout loop. | Medium | Medium | Hosting controllers are reused and never recreated on state updates; lazy loading of the neighbouring pages with prefetch. Closed. |
| R13 | Fast inertial swipes outrun lazy page loading. | Medium | Medium | Prefetch of pages before the snap settles. Closed. |
| R14 | Accidental use of APIs newer than iOS 15 (`@Observable`, `scrollTargetBehavior`, `@Entry`, ...). | Medium | Medium | The deployment target is iOS 15; builds use the iOS 15 triple; forbidden symbols are audited before releases. Open. |
| R15 | Conflicts between parallel contributors editing the same files. | Medium | Medium | Disjoint file scopes per change; review of the full diff. Closed as a process risk. |
| R16 | Regression after merging into the integration branch. | Medium | Low | Rebase on the latest base and run the full suite. Closed as a process risk. |
| R17 | Code diverges from the design documents. | Medium | Medium | Any deviation updates the document in the same change; each design document has a section on implementation deviations. Open. |
| R18 | The scope of StartScreen was underestimated. | High | Medium | Hard MVP boundaries; the cut features are listed under known limitations. Closed: the component is complete. |
| R19 | Plans and registers go stale. | Process | Medium | Retired: the tracking files were replaced by the decision log, this register, the changelog and the manual checklist. Closed. |
| R20 | The contract of drag physics and gestures in StartScreen changed several times (merge hold re-arming, hit testing against the base layout, drag targets moving from order slots to cells); regressions are likely when it changes again. | High | Medium | The windowed drag tests (`DragSessionTests`, `DropSlotTests`, `TileCellDragTests`, `TileMergeHoverTests`, `TileMergeZoneTests`) must pass; before releases run the manual checklist on the Example's Start tab. Open. |
| R21 | Behaviour changes for hosts: `folderTapHandler` is also called in edit mode, folders get a localized default name, panel titles keep their case, new folders are always medium, move callbacks changed shape (`didMove(_:toFolder:atCell:)`). | Medium | Medium | Listed in the changelog; a minor version bump rather than a patch; deviations are documented in the StartScreen design document. Closed with 1.0.0 (the API is now stable). |
| R22 | A non-canonical model order (grid order differing from reading order) made a drop place a tile in the wrong spot. | Medium | Medium | Closed: positions are explicit cells and reading order is derived (D30); canonicalisation was removed. |
| R23 | Holes in the layout absorbed tiles because packing was strictly compact; a tile could not be pinned into a specific hole. | Medium | Medium | Closed: real holes were implemented (D30, D31); drops choose the cell under the finger. |
| R24 | Verification gaps: live visuals of drag (merge highlight, haptics, rotation mid-drag), VoiceOver, RTL and Dynamic Type of the full start screen, and animations of previews and folder dissolution are not verified on a device; simulators are shared between parallel sessions. | Medium | Medium | A dedicated simulator or device for manual runs; the manual checklist; regressions covered by windowed tests (see R20). Open. |
| R25 | Migration of `tiles.json` v1 to v2 writes lazily (on the first call with a grid width) and was not checked on a real user file; an older library version cannot read a v2 file (a newer version is treated as unsupported: a backup is kept, state is unchanged). | Medium | Low | Persistence tests cover the round trip, migration, invisible keys and a corrupted file (never overwritten); a manual run with a v1 file is on the checklist; downgrading the library is not supported. Open. |
| R26 | The VoiceOver order by cells is derived from code (UIKit traverses cells by collection index, `accessibilityElements` is not set); not confirmed with VoiceOver on a device, nor the focus after unpin, resize, drop and folder dissolution. | Medium | Medium | The snapshot order equals the reading order (`TileAccessibilityOrderTests`); check on a device, including a scrolled grid; if it diverges, set `accessibilityElements` explicitly. Open. |
| R27 | The push-down cascade (D31) and folder dissolution (D45) can change the screen unexpectedly: a growing tile moves distant tiles down the column, a dissolved folder is replaced by a tile of another size, and a collapsing drop yields two `onChange` calls. | Medium | Medium | Behaviour is documented in the StartScreen design document and the conformance review (D45 is a deliberate deviation); guarded by `TileLayoutEnginePlacementPropertyTests` and `TileStoreFolderMinTwoTests`; replacement and panel-close animations are on the manual checklist. Open. |
| R28 | In-panel reordering mixes two drag modes in one gesture (reorder, then take-out after leaving the panel by 16 pt); panel tiles shift by writing frames directly, so an external reconfiguration mid-drag (width change, rotation, a foreign snapshot) cancels the reorder; tall panels with auto-scroll and RTL are verified only in tests and without a finger. | Medium | Medium | One path: the reorder session is replaced as a whole by a take-out with no way back; drag-session consistency cancels the reorder on any external change; tests in `TilePanelDragReorderTests`; manual checklist. Open. |
